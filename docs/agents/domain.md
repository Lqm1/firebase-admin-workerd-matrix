# Domain docs

This repo uses one context. Read the root `CONTEXT.md` before work that depends on domain terms. Read relevant decisions under `docs/adr/` before changing an area they cover.

These files are created as terms and decisions are settled. If a file does not exist yet, continue without it.

Use the vocabulary defined in `CONTEXT.md` in issues, specs, code, and tests. If a concept is missing, record the gap for `/domain-modeling`.

If a proposed change contradicts an ADR, identify the ADR and explain why the decision should be revisited.

## Layout

- `CONTEXT.md`: shared domain vocabulary
- `docs/adr/`: architecture decision records
